# 开源发布调研报告（2026-10-24）

> 调研对象：Vibe Guard（代码包名 vibe-sec-platform）v0.5.0
> 调研环境：Windows 11 + Python 3.11.6 venv，GitHub 公开仓库 dxz0069/vibe-guard
> 调研方式：本地健康检查 + 全量测试 + 静态分析 + 外部竞品检索

## 1. 执行结论

项目整体质量好于典型比赛作品：**227/228 测试通过（1 项平台性 flaky，已修复）**，无密钥泄露、无机器路径残留，架构文档诚实标注了能力边界。达到开源发布标准，主要短板在**仓库工程化配套**（LICENSE 缺失、占位链接、无 CI）与**代码风格债**（3212 条 lint，96% 为 py311 风格现代化），本次已修复前者并建立 CI 门禁，后者建议按路线图分批处理。

## 2. 本地验证结果

### 2.1 测试套件（Python 3.11.6）

| 指标 | 结果 |
|---|---|
| 通过 | 224 通过 + 1 跳过（Docker 镜像不可用时自动跳过） |
| 修复后复跑 | 227 通过（含修复的 flaky 用例） |
| 环境性失败 | 2 例：tree-sitter-language-pack 运行时从 GitHub 下载解析器被网络策略阻断（对应项目已知问题 #3） |
| 逻辑性失败 | 1 例：`test_api_validation_results.py::test_project_finding_queue_clusters_completed_task_results` |

逻辑性失败根因：`api/server.py:944` 以 `completed_at or created_at` 排序取"最新任务"，Windows 时钟分辨率约 15ms，测试中两个连续 `datetime.now()` 取到相同时间戳，稳定排序保留插入顺序导致断言翻转。Linux 纳秒级时钟不触发，属跨平台 flaky。已通过显式时间戳修复（提交 9a26615），8/8 用例通过。

### 2.2 静态分析（ruff，按仓库自带配置）

| 规则 | 数量 | 性质 |
|---|---:|---|
| UP006/UP045/UP035 等 py311 风格现代化 | ~3080 | 风格债，2092 条可 `--fix` 自动修复 |
| E501 行超长 | 919 | 风格债 |
| F401 未使用导入 | 2 | 真实错误，已修复（generate_docx.py） |
| 其余（SIM/N/A 等） | 少量 | 低风险 |

注意：**不建议在无法回归验证的大批量改动中直接 `ruff --fix`**——pydantic 会运行时求值类型注解，UP045（`Optional[X]` → `X | None`）涉及 394 处，应在 CI 绿灯后小批量提交。CI 已用 `--select F,E9` 建立错误级门禁。

## 5. 竞品与生态调研（2026-10 检索）

- 开源同类以轻量方案为主：[benavlabs/vibe-check](https://github.com/benavlabs/vibe-check)（安全清单 + 审计提示词，让 AI 自查）、[Vibe Code Scanner](https://vibe-eval.com/vibe-code-scanner)（在线探测 AI 生成站点的失败模式）。
- 行业数据印证赛道：[Escape.tech 对 5600 个 vibe-coded 应用的扫描](https://www.ox.security/blog/vibe-coding-security)发现 2000+ 漏洞、400+ 暴露密钥；[CSA 研究笔记](https://labs.cloudsecurityalliance.org/research/csa-research-note-ai-codegen-vulnerability-debt-20260406-csa)确认 74 个 AI 关联 CVE，45% 的 AI 生成代码方案含设计缺陷。
- **差异化定位**：本项目是开源阵营中少有的"完整平台"（确定性多智能体编排 + VRTM 四平面建模 + 三态验证 + 结构化整改回送），vibe-check 类清单方案不构成直接替代。建议对外传播强调：本地可跑（零外部服务依赖）、证据分级诚实（needs_evidence）、修复指令直接进 AI 上下文。

## 6. 优化路线图（建议优先级）

1. **P0 离线可用性**：解决 tree-sitter 解析器运行时下载（vendor 或环境变量指定本地目录），否则离线/受限网络下 TypeScript AST 通道全部降级。
2. **P0 验证能力**：扩大验证白名单覆盖（已知问题 #2），在保守三态框架内提升 verified 比例；建议先从 SQL 注入、命令注入两类高确定性漏洞突破。
3. **P1 召回率基线**：作品自述 VAmPI 6 个已知漏洞仅命中 1 个（16.7%）。建议建立固定的靶场基准脚本（VAmPI + Juice Shop + Agent fixture），每次迭代输出精确率/召回率对比，防止能力回退。
4. **P1 lint 分批清偿**：CI 绿灯后按目录分批 `ruff --fix`（每批跑全量测试），先 UP035/UP006 后 E501。
5. **P2 TriggerPolicy 内容级匹配**（已知问题 #4）、RiskChain 边界假设细化（#5）。
6. **P2 仓库工程**：发布 PyPI 包（当前仅 git 安装）、pre-commit 钩子、README 英文化全文。
